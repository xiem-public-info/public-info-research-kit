# 公开信息研究决策手册

收到用户或下游的检索合同，即默认授权全部检索渠道和公开搜索表面按需使用。下游只给业务目标、主体和内容需求；本工具包选择渠道、AI 使用顺序和精确词。AI→原文、原文→AI→后续计划均属常规研究。每条查询提交前冻结，范围内迭代无需另批；超出对象、目标或预算才请求裁定。权限不代表工具、登录、访问或真实渠道已验证。

本手册保留可迁移、可执行的经验结论，不收录研发事故流水、账号态、真实业务样本或已退役实现。

| 可观察情形 | 归类 | 必须动作 | 禁止动作 |
|---|---|---|---|
| 查询未被正确提交，结果页没有刷新 | `query_transport_failure` | 只按渠道画像允许的一次低风险纠正处理；仍不确定则停止 | 不记成语义失败，不连续重复提交 |
| 微信直接粘贴动作报告错误，但最新完整画面逐字显示完整精确词 | `operator_transient_error_recovered` | 以最新可见画面为准，继续一次提交 | 不二次粘贴，不把动作错误直接等同于界面失败 |
| 微信画面不可观察或状态有歧义 | `route_control_failure` 或 `safety_stop` | 放弃当前查询并保留停止原因 | 不重复危险动作，不启用 V2、Pad、AX、DOM、固定坐标或自动回退 |
| 小红书出现调试、自动化接管、异常 profile 或验证码／风控提示 | `route_control_failure` 或 `safety_stop` | 立即停止并交由终端用户处理 | 不切换到 Playwright、CDP、DOM、隔离 profile 或历史采集器 |
| 列表标题看似相关，但正文未打开 | 尚未形成正文证据 | 继续按冻结的实际开读下限开文 | 不把标题浏览计入 `actual_open_count` |
| 两个确有内容推进的结果批次仍无高质量候选 | 语义、身份或供给缺口 | 分层归因；形成下一批提案或停止 | 不只凭“无结果”断言全网没有 |
| 发现同名项目、跨城市对象或历史名混入 | `identity_collision` | 排除、记入 `negative_hits`，重新闭合对象身份 | 不计入合格样本，不把排除项静默丢弃 |
| 当前查询重复率高且边际增益低 | 供给 gap 或语义效率低 | 记录边际信息增益；形成范围内迭代或超范围提案 | 范围内使用 `in_scope_iteration_batch`；超范围须另获授权 |
| 增量批次已获业务 Owner 授权 | `approved_incremental_batch` | 按原任务覆盖的公开表面逐条冻结查询并确认实际工具、登录、访问和桌面条件 | 超范围变化才另请裁定，不重复索取逐渠道权限 |
| 某查询在单个任务中表现良好 | `candidate` | 有可复用经验时保留去标识的方法记录，等待跨任务验证 | 不直接晋升为推荐模板 |
| 同一业务问题族中跨至少两个真实任务有效，且真人批量复核接受 | `recommended` | 在具名业务问题族中晋升并保留复核回执 | 不跨业务问题族无条件外推 |
| Feed、搜索摘要、转载或 AI 聚合命中 | 发现线索 | 回到官方或真实可见原文后再升级 | 不直接当事实、用户声音或市场比例 |
| 任务同时提到微信 AI 搜索和小红书问点点 | 两个独立的 `platform + aggregate_surface_id` | 继承同一任务授权，分别记录表面、线索和普通原文回源面；普通搜索不得冒充聚合表面 | 不合并成一个“AI 搜索”回执，不跨平台替代 |
| 住宅比较对象距交付不足 12 个月 | 当前供给需要复核 | 核目标产品余量、实际可选房源与销售重叠；尾盘建议另需库存和销售阶段依据 | 缺依据时资格待核，不因交付距离自动降级 |
| 住宅比较研究首次回传的项目事实、竞品关系、客户选择和反例不能共同支持统一语义核 | `partial` 或 `unsupported` | 返回一份合并增量提案并说明预期信息增益 | 范围内按任务合同继续；超范围不执行 |
| 同一家庭比较多个项目 | 多项目事件归属、单一全局家庭旅程 | 项目归属分别保留，全局独立家庭旅程只计一次 | 不把正文作者与评论者拼成同一家庭链 |
| 任务需要官方表达资产但材料只有摘要，没有必要短原话或原文定位 | 官方表达资产未完成 | 同时保留核心观点、必要短原话、标题／主体／日期／生命周期和原文定位 | 不把摘要标成完整官方表达资产 |
| 当前检索任务仍在进行但线程变慢 | 任务尚未自然闭合 | 先区分页面、GUI 与上下文压力，并完成或安全停止当前任务 | 不催促、不插入下一批、不提前换线程 |
| 只有个人公开表达、营销叙事或平台观察 | `soft_evidence` 或 `platform_observation` | 明确允许用途和 `blocked_use` | 不进入项目硬事实或市场总体判断 |
| 上游已完成证据包 | `fulfilled`、`partial`、`gap` 或 `stopped` | 保持 `downstream_acceptance=not_assessed`，由下游独立决定 | 不把上游完成写成下游接受 |
| 没有冲突或缺口 | 合法空集合 | 分别写 `conflicts: []`、`gaps: []` | 不省略字段，不写 `null` |
| OSM 图件显示清楚，但锚点、POI、坐标或距离未核验 | 仅显示资产可读 | 分别验收空间事实与客户面显示 | 不用“图看起来对”替代空间事实验证 |

所有规则都受当次任务范围、终端用户授权、渠道画像、来源许可与停止线约束。离线回归通过只证明合同和拒收逻辑可执行，不证明某台电脑已完成真实渠道 smoke 或业务验收。

图片按对象、视角和用途缺口选源；普通研究可先用已有截图，正式入选图片按清晰度需求补取。完整购房事件的希望取得进展按下游既有定义记录，不扩成全渠道统一强制字段。空间合法缺口允许部分交付，近似材料不冒充精确位置，任务完成由业务目标决定。

## 任务理解与计划一致性

模型结合原请求、前期上下文和当前补充指令确定业务领域及任务范围；通用 QA、分类等词只作线索。收到的 `retrieval_task` 保持原样，原文可放其已有 `request_text`，缺省回指 `business_question`。继承的 `business_domain` 使用 residential、non_residential 或 unknown；已有领域不得由本轮通用词覆盖。

在现有 Owner 计划内记录 `scope_interpretation`：绑定同一 `task_id`、完整 `request_text`，写明 `domain`（没有继承领域时用原文 `domain_basis`）、`research_required`，把动作写入 `actions`（唯一 id、原文 request_quote、既有 route_id），明确不做的能力及原句放入 `exclusions`，待解释原句放入 `unresolved_items`。`action_coverage` 按动作 id 记录 execute、reuse 或 defer；复用附 evidence_refs，暂缓附 reason。有范围解释的计划中，每条查询用 action_id 回指执行中的动作。所有字段由本包依据原任务生成，不要求使用者填写。

`tools/retrieval_task_policy.py` 校验绑定、计划遗漏、排除冲突、领域冲突与原研究标准，`tools/compile_retrieval_execution_request.py` 实际消费校验结果。有冲突先订正本包计划；缺解释时已明确的独立部分可继续，不能把待解释项当成整套资格审查或额外搜索命令。轻量资格范围不自动豁免研究充分性；指定读取仍用原有直接读取适用性接口，原任务研究标准仍保留。

一致性通过只证明所记录解释与计划一致。代码不能证明模型没有漏解原话、引文的语义正确、复用来源已被读过或任务已充分；执行者仍须回看原任务。预检通过、实际渠道执行、回传、正文消费、用户验收、发布分别报告。下一次自然业务任务检验实际调用与回传，不为离线修正另造平台任务。
